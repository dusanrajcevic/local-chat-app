# Local AI Chat Saver Extension

This browser extension adds Local Chat controls to supported AI chat websites and sends selected messages to the local app running on your machine.

## Supported sites

- ChatGPT
- Claude
- DeepSeek
- Gemini

Support is best-effort. The extension relies on provider DOM structures and copy/composer controls, so provider UI changes can break capture.

## Setup

1. Start Local Chat App with `npm start` or the desktop app.
2. Open `chrome://extensions`.
3. Enable Developer mode.
4. Click **Load unpacked**.
5. Select this `browser-extension/` directory.
6. In Local Chat App, click **Pair browser extension** and generate a short-lived pairing code.
7. Open the extension popup and confirm the local URL, usually `http://localhost:3000`.
8. Enter the pairing code and click **Pair**.

The pairing token is generated by the server, bound to the extension ID, and stored by the extension in a storage area restricted to trusted extension contexts. The popup accepts only `http://localhost[:port]` or `http://127.0.0.1[:port]`; remote hosts, credentials, HTTPS, paths, queries, and fragments are rejected. Pairing is the normal browser-extension setup; the optional server-side manual-token fallback is intended for compatible API clients rather than popup configuration.

## Behavior

- `providers/*.js` define provider-specific host matching, turn selectors, content selectors, and sender/container preferences.
- `content-providers.js` loads those adapters and exposes the registry.
- `content-dom.js` owns shared DOM/message extraction orchestration.
- `content-diagnostics.js` produces privacy-preserving provider health reports with selector/message counts and warnings; the popup exposes them through **Diagnose page**.
- `content-compaction.js` defines the provider-facing handoff protocol, request IDs, structured/plain response normalization, legacy-envelope compatibility, and conversion to the local compaction API payload.
- `content-compaction-workflow.js` drives Compact end to end: send the handoff export request, associate the exact provider response, persist it, activate the compacted child, and hide implementation turns.
- `content-message-save.js` owns selected-text preference, provider clipboard capture/restoration, DOM fallback, and visible-message-container filtering for manual/autosave extraction.
- `content-autosave.js` owns autosave state, assistant-readiness tracking, idempotency-key generation, prompt-capture scheduling, and outgoing/assistant save dedupe.
- `content-sidebar.js` owns local sidebar replacement, provider-sidebar hiding/restoration, folder/session rendering, refresh, and session-selection behavior.
- `content-composer.js` owns composer detection, transcript insertion, pasted-text attachment fallbacks, Load past conversations modal/search behavior, and top active-folder controls.
- `content-runtime.js` owns local-app availability checks, auto-save toggle UI/state, Save local target selection/injection, and content-script scheduling.
- `content.js` is the small bootstrap/coordinator that wires the modules together.
- `local-api.js` validates the loopback-only API origin shared by the popup and background worker.
- The background worker owns all API calls to the local app, attaches the paired token only after destination validation, applies request timeouts, revalidates cached GETs with ETags, and requests bounded session/recent/search windows where the UI already has a limit.
- Autosave captures submitted user prompts and completed assistant responses when enabled.
- Autosave sends idempotency keys so repeated DOM events do not append the same message multiple times. This behavior is covered by unit tests in `test/content-autosave.test.js`.
- Sidebar behavior is covered with jsdom fixture tests in `test/content-sidebar.test.js`, including folder/session rendering, session selection, refresh, and native-sidebar hide/restore. Composer and Load past behavior is covered in `test/content-composer.test.js`. Message extraction/clipboard behavior is covered in `test/content-message-save.test.js`. Runtime toggle/availability/Save local behavior is covered in `test/content-runtime.test.js`. Provider diagnostics and mutation-resistance checks are covered in `test/provider-diagnostics.test.js`.
- The selected local session is captured at submit time so a later active-session switch is less likely to save the assistant response into the wrong chat.

## Provider handoff protocol

The Compact workflow uses a provider-facing `local-chat-handoff` export protocol rather than asking the provider to perform or describe conversation compaction. Each request carries a unique `handoff:req:...` request ID and asks for one JSON payload between explicit `LOCAL_CHAT_HANDOFF_RESPONSE_V1` markers. The parser requires the expected protocol name, version, request ID, and a non-empty handoff message. Legacy `LOCAL_CHAT_COMPACTION_*` envelopes are still recognized so existing provider turns remain safe to ignore.

The background worker still exposes `UPSERT_LOCAL_CHAT_COMPACTION`, which forwards the normalized `{ requestId, compactedMessage, providerKey }` payload to the existing `PUT /api/sessions/:sessionId/compaction` endpoint. The local sidebar exposes **Compact** for the active chat. The workflow records which assistant turns existed before sending, associates the first assistant turn after the exact handoff request, and prefers the structured envelope. If a provider ignores the envelope but returns a completed plain-text handoff, that exact associated turn is accepted as a fallback instead of timing out or accidentally reusing an older assistant message.

Handoff request/response turns are implementation details: autosave ignores structured protocol text, associated request/response containers are marked by the workflow, Save local controls are not injected for marked turns, and those turns are hidden from the provider conversation UI. The sidebar reports each workflow stage (sending, waiting for the provider, saving, and opening the compacted continuation), exposes cancellation while it is still safe before persistence, and shows retry/dismiss controls after terminal errors. A compaction is also cancelled if the active local session or provider conversation changes while it is running, and concurrent Compact requests are rejected. Compacted child sessions are identified in the local chat list.

## Provider diagnostics

Open a supported provider chat and choose **Diagnose page** from the extension popup. The report shows the detected adapter, selector hit counts, message-level copy controls, discovered/extractable message counts, inferred user/assistant coverage, streaming markers, and warnings. It intentionally does not return message text, chat titles, or the current page path. Use it after a provider UI change to identify whether the adapter, sender inference, copy-control detection, or extraction path is degrading.

## Limitations

- DOM extraction is heuristic, although provider-specific selectors are isolated in `providers/*.js`, covered by reduced provider fixtures, and exercised against wrapper/class/test-id mutations that preserve semantic message structure.
- Long chats can stress provider pages and the content script.
- Background-worker URL/header/session behavior is covered by Node tests. Reduced provider DOM fixture tests cover extraction and Save local injection for ChatGPT, Claude, DeepSeek, and Gemini, composer tests cover modal search/rendering and transcript insertion, and runtime tests cover auto-send toggle state, local-app unavailability cleanup, and Save local delegation. These are regression tests, not a guarantee that live provider DOM changes will keep working.
- Clipboard permissions are used only for capture/paste flows initiated by the extension logic.
